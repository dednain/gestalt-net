One rule: wait for the third sentence

The reader consumes non-overlapping triads τk = (s3k−2, s3k−1, s3k). No decision about an object in CURRENT is emitted until AFTER has been read. That single gate is the whole architecture.

BEFORE
The butler took out a white handkerchief.
→
CURRENT
He wiped his forehead with it.
→
AFTER · decision fires
He calmly put it away and trimmed the hedge.
Why it matters. A scene that closes is erasable. A scene ending in "he frightenedly hid the scar on his sleeve and ran" is not — the emotion is unresolved, so the scar goes to the Dossier. After training, the model's summed absolute weight on AFTER features is 25.8 versus 9.5 on BEFORE features: it learned to wait, without being told which sentence matters.

Three boxes of memory

Replace retained prose with tags and triggers. No quantisation, no pruning, no attention kernel — just retrospective logic.

📦

Dossier

Eternal short tags on characters: [Butler] → crescent scar (p. 12). Permanent traits, strange reactions and suspicious contrasts survive; the long sentences do not.

O(entities) · 100% precision
🗑️

Trash

Closed domestic actions are erased completely from working memory. Empty by definition, so it costs nothing. Around 90% of the scene volume ends here.

0 bytes retained
📡

Sleep-Triggers

Written before deletion: handkerchief = Butler (p. 12). Five hundred pages later a white handkerchief appears at a murder scene — an O(1) dictionary lookup fires and the owner is recalled.

~22 bytes each · O(1) recall
B_full  = Σ bytes(sentence)                          = 478,193 bytes
B_ges   = Σ bytes(dossier tags) + Σ bytes(triggers) =  64,716 bytes
saved   = 1 − B_ges / B_full                        =     86.5%
ratio   = B_full / B_ges                            =      7.4×

Honest scope

We did NOT measure VRAM. The 86.5% is UTF-8 bytes of retained text context — not GPU memory, not KV-cache bytes, not a measured transformer speedup. Translating it into VRAM savings needs a real model integration, which has not been done.
  • Not a transformer, not an LLM. The triad judge is a linear bag-of-stems logistic scorer with 198 weights. In production an LLM would be the judge; the three boxes are the memory around it.
  • The corpus is synthetic — templated Russian detective stories. The 100% accuracy is on those books, not on real literature. Real prose needs proper NER, coreference and irony handling.
  • The label is a dense surrogate ("should this object be in the Dossier"), derived from whether the final answer needed it — not full RL from one end-of-book reward.
  • Stems, character names and cue words are hand-listed lexicons. The decision is learned; the perception is not.
  • A surprising ablation: an untrained network still answers 100% correctly because triggers insure against bad decisions — its Dossier precision is just 7.5%. Training buys compression and a clean Dossier, not raw correctness.
